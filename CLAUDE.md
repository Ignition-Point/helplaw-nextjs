# Help Law Group — Project Context

## What This Is

A Next.js website for **Help Law Group**, a legal advocacy organization that connects survivors of abuse, unsafe products, and institutional harm with mass tort and class action attorneys. Client contact: **Ashley** (handles content). **Sarah** owns this project.

**Live site:** helplaw-nextjs.vercel.app
**Production domain:** helplaw.com (metadata references this)

## Tech Stack

- **Framework:** Next.js 16 (App Router, React 19)
- **Styling:** TailwindCSS 4 with custom design tokens (navy, gold, warm-slate color palette)
- **Database/CMS:** Supabase (Postgres + RLS)
- **Hosting:** Vercel (auto-deploy from GitHub main)
- **Forms/validation:** Custom, no react-hook-form
- **Icons:** lucide-react
- **Notifications:** sonner

## The Three-Layer Architecture

```
GitHub (code) → Vercel (hosts, builds, serves) → Supabase (content & leads)
```

- **GitHub** holds code only. No content.
- **Vercel** auto-deploys from main. Environment variables (Supabase keys) live in Vercel dashboard, not in the repo.
- **Supabase** holds all dynamic content. Lovable has its own CMS UI that reads/writes to the same Supabase database Ashley uses for day-to-day content work.
- Pages use `export const revalidate = 60` — CMS changes propagate within 60 seconds without a deploy.

|-------|---------|

| `lead_submissions` | Lead captures — linked to `lead_form_id` and optional `case_id` |
| `blog_posts` | Published articles (SEO fields, featured_image, content HTML, author_name) |
| `blog_post_faqs` | FAQ pairs for blog posts |

### RLS Policies (Important!)
- Anon key can **SELECT only active/published** content. Draft records are invisible to it.
- Anon key can **INSERT** lead submissions and cases.
- Anon key **cannot UPDATE or DELETE**. Fixes to existing records must be done in Lovable's CMS or via SQL run by the user.
- This is why draft case slug collisions are confusing — the parser's "slug doesn't exist" check passes (can't see the draft), then the INSERT fails on unique constraint.

## The Case Creator Tool — `/admin/create-case`

Lets Ashley paste a Google Doc URL to auto-generate a case in the CMS. The entire parser is in `src/app/api/create-case/route.ts`.

### How the parser works (after the big rewrite)
- Google Docs export is **plain text**, not markdown. No `**bold**` markers. `\r` line endings. `________________` is the horizontal rule.
- **Phase 1:** Extract metadata from the top ~40 lines by reading `Field: value` lines (Title, Slug, Category, Case Type, Background Image, Eyebrow, Subheadline, SEO Title, Meta Description, Focus Keyword, Secondary Keywords).
- **Phase 2:** Split remaining content into blocks by horizontal rules. First line of each block = heading.
- **Phase 3:** Classify each block — Table of Contents (skip, auto-generated), FAQ, MID-PAGE CTA, CLOSING CTA, LEAD FORM, Disclaimer (skip), otherwise regular section.
- `bodyToHtml()` converts plain text to HTML (sub-headings, bullet lists, timeline date markers).
- Variant hints: `(Dark)` or `(Light)` after heading text.
- Auto-detects category from title keywords if not specified.

### Template
Ashley gets the standardized template at `public/case-page-template.docx` (downloadable from `/admin/create-case`). It's generated by `scripts/build-template.js` using docx-js. **Settings tab fields are the critical part** — that's where things historically broke. Page content blocks are flexible.

## Common Gotchas

1. **Draft cases are invisible to the anon key.** If a slug check passes but INSERT fails on unique constraint, it's probably a draft collision. Fix in Lovable or via SQL.
2. **Lovable's category dropdown** doesn't match the real categories — that's in Lovable's code, not this repo. Can't fix from here.
3. **Top-level await fails** in `npx tsx -e` scripts. Wrap in `async function main(){}; main();`.
4. **Don't assume `**bold**`** markers when parsing Google Docs — the export API strips all formatting.
5. **Image paths starting with `/uploads/`** are gitignored. Move to `/images/` for anything needed on the live site.
6. **Sticky mobile CTA** hides on desktop (md breakpoint). Don't add duplicate CTAs on mobile.
